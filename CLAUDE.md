## The thesis, in one paragraph

Every B2B company routes inbound leads with an ordered list of rules. That list is a **program** —
branching control flow over typed inputs with a fallthrough default — and it is the only program in
the company that ships with no tests, no coverage report and no linter. Rules die silently (a broad
rule added in month three makes a narrow rule added in month nine unfireable, forever, with no
output anywhere that says so); the ruleset has holes whose *shape* nobody can describe; overlap is
resolved by line number rather than by decision; and assignment is presented as a function of the
lead when a round-robin counter is actually picking the person. This repo treats the ruleset as an
analysable artifact and **proves** things about it: which rules can never fire, which regions of
lead-space no rule claims, which leads two rules both claim, and what a pending edit will move. The
proofs are exact — not sampled, not solver-approximated — because the rule language was deliberately
restricted until exactness was cheap. Sibling repos own the neighbours: Day 001 `icp-score` owns
weighted arithmetic, Day 012 `icp-diff` owns definition comparison, Day 016 `territory-builder` owns
drawing territories, Day 029 `lead-sla-monitor` owns the clock, Day 033 `routing-simulator` owns
volume over time. **Do not rebuild any of them here.** Day 009's only claim is static analysis of
the ruleset.

`npm` is the committed package manager — README and lockfile stay npm even if bun is used locally,
because `npm install && npm run dev` is what a reviewer types without reading.

Five setup facts inherited from Days 001–008:

- Vitest config belongs in `vitest.config.mts` (`.mts`, not `.ts` — the extension is what stops
  Vite's config loader warning about ESM-in-CJS), and it globs `lib/**/*.test.ts` only. Tests
  outside `lib/` will not run.
- `tsc` alone fails on a clean checkout because `LayoutProps` and friends are generated into
  `.next/types`, so `typecheck` must run `next typegen` first. Never "fix" that error by editing
  `app/layout.tsx`.
- `tsconfig.json` sets `noUncheckedIndexedAccess` on top of `strict` — array and record access
  yields `T | undefined`. Handle it; do not reach for `!`.
- Scripts run through `vite-node -c vitest.config.mts` rather than bare `node`, because the engine
  uses extensionless relative imports that Node's ESM resolver rejects and the `@/` alias lives in
  the Vitest config.
- `AGENTS.md` is regenerated by `next dev`. Commit it with your work; deleting it from a diff only
  re-creates the uncommitted change.

## Architecture

```
                    ┌─ server component ──► data/*.ts (Zod-validated at import)
Browser ────────────┤
                    ├─ lib/routing (pure) ──► same functions client- and server-side
                    │
                    └─ POST /api/translate ──► key check ──► rate limit ──► model ──► Zod ──► Rule (unrun)
```

`lib/routing/` is the engine and is **dependency-free and framework-free** — it imports `zod` and
nothing else. Not `next`, not `react`, not `@/data`, not `@google/genai`, no DOM globals. An eslint
`no-restricted-imports` rule scoped to that directory enforces it and the package carries its own
`README.md`. This is not stylistic: an analyser that cannot reach a network client or a database
cannot emit a finding that isn't a consequence of its arguments.

| module | responsibility |
|---|---|
| `types.ts` | the type contract — fields, domains, conditions, rules, targets, outcomes, findings |
| `domains.ts` | the eight declared field domains; the only place a field's universe is written down |
| `schema.ts` | Zod schemas for corpus and ruleset; parsed at import, throws on bad data |
| `condition.ts` | constraint algebra — intersect, subset, complement, isEmpty, per field |
| `grid.ts` | cut-point decomposition, cells, region union/difference, region → prose |
| `route.ts` | the pipeline, steps 1–3; pure |
| `select.ts` | step 4 — three strategies, capacity; the only stateful module |
| `analyze.ts` | the eight static findings, over the grid |
| `empirical.ts` | the three corpus findings, over corpus leads |
| `diff.ts` | blast radius — assignments under ruleset A vs ruleset B |
| `export.ts` | CSV serialisation, permalink encode/decode |

`data/` holds the corpus (~12 reps, ~26 accounts, ~70 leads, a 19-rule default ruleset, 4
presets). `lib/translate/` holds the Gemini call, prompt, response schema and rate limiter. `app/`
is the single console: Ruleset · Space map · Findings · Leads.

### The pipeline

```
lead
 ├─ 1. PRE-EMPTION   emailDomain → account → active owner?    ──► PREEMPTED  (stop)
 │                                          → inactive owner? ──► BLOCKED    (stop)
 ├─ 2. MATCHING      evaluate ALL rules  → full match set     (analysis)
 │                   first enabled match → winning rule       (decision)
 ├─ 3. ELIGIBILITY   winning rule.target → eligible rep set   (pure) ── empty? ──► BLOCKED
 ├─ 4. SELECTION     strategy + capacity → one rep            (stateful, NOT analysable)
 └─ (no rule matched)                                         ──► FALLBACK
```

**Steps 1–3 are a pure function; step 4 is the only place state enters.** Everything the analyser
claims is a claim about steps 1–3. The engine ships to the browser — editing a rule must re-derive
every finding and every assignment with no round trip.

**Domains, rules and the corpus are data, not code.** If you find yourself writing
`if (countryId === "FR")` inside `lib/routing/`, the fact belongs in `data/` or `domains.ts` as a
field on a record instead.

## Rules that are easy to break by accident

- **Never add a score.** Decision 17. No 0–100, no "routing health", no percentage that gets summed
  or sorted on. Findings are typed and counted per class. A number is how this project turns back
  into Day 001.
- **Never report "% of lead-space".** Cell count is not lead volume — a percentage would assume a
  uniform distribution over leads, which is false. An uncovered region gets a **description** and a
  **corpus lead count**, nothing else.
- **Proofs and observations never mix.** Static findings are true of the whole lead-space; empirical
  findings are true of 70 authored leads. Separate sections, separate counts, never summed into one
  total. Conflating them is the mistake the repo exists to refuse.
- **The rule language stays inside the decidable fragment.** Conjunction of at most one constraint
  per field over declared domains. No disjunction inside a rule (write two rules), no cross-field
  comparison (`a > b`), no arithmetic, no regex. The moment any of those land, every finding
  downgrades from a proof to a guess, and the whole thesis is gone. Expressiveness was traded for
  exactness on purpose, and the README says so.
- **`⊥` is a domain value, not a third truth value.** Missing/unenriched is a member of the domain;
  a constraint admits it only if written to. Do not introduce three-valued logic — it destroys the
  exact set algebra and buys nothing that `ENRICHMENT_DEPENDENT` doesn't already say better.
- **Order decides, but all rules are evaluated.** First-match-wins produces the assignment; the full
  match set is still computed, because shadowing and contest are only nameable if you kept it.
- **Targets resolve to rep *sets*, never to a person.** A target that returns one rep directly makes
  `NO_ELIGIBLE_OWNER` uncomputable and smears step 3 into step 4.
- **Capacity lives on the selection side and cannot move a finding.** The sweep sets every capacity
  to 0 and then to 10000 and asserts the finding set is byte-identical. If a capacity change alters
  an analysis result, the change is wrong, not the invariant.
- **`BLOCKED` does not fall through to the rules.** A pre-emption pointing at a departed rep is a
  black hole; quietly falling through is how the black hole survives for two years. Surfacing it is
  the product.
- **The space map always prints its pinned slice.** A 2-D view of an 8-D space is a projection.
  Rendering it without naming the six pinned values is lying with a picture.
- **`ROUND_ROBIN` and `LEAST_LOADED` are labelled not reproducible in the UI**, and a test asserts
  they actually aren't — the label is backed by evidence, not by a claim.
- **The corpus is authored and synthetic.** Every domain ends in `.example`; no real company or
  person is described. Traps are named, and each has a test named after it.

## Gemini conventions (inherited from Days 001–008)

`@google/genai`, model `gemini-3.6-flash`, `responseMimeType: "application/json"` with a native
`responseSchema`, then Zod as the trust boundary — a schema is a request, a validator is a
guarantee. `ThinkingLevel.MINIMAL`: this is constrained translation against a fixed schema, not
reasoning. `temperature: 0`.

Missing key → **501** with a message pointing at the builder. Model failure → **502**. The app must
render every rule, every finding, the space map, all four presets, the permalink and the CSV with
`GEMINI_API_KEY` unset. **The model never routes, never analyses, never resolves a contest** — its
one job is prose → `Rule`, landing in the builder unrun, editable, and disabled by default.
